# AgriOpportunities — Expo frontend

Expo Router app (React Native + web) for discovering agricultural bursaries,
learnerships, internships, graduate programmes and jobs. All runtime data comes
from the authoritative `AgriOpportunity_Supabase` project through Supabase Auth,
the anon key and row-level security.

## Requirements

- Node.js 20+
- Expo Go on a device, or an Android/iOS simulator, or a browser
- A Supabase project with migrations `001`–`013` applied

## Setup

1. Copy the environment template and fill in the project values:

   ```powershell
   Copy-Item .env.example .env
   ```

   ```env
   EXPO_PUBLIC_SUPABASE_URL=https://<project-ref>.supabase.co
   EXPO_PUBLIC_SUPABASE_ANON_KEY=<anon-key>
   EXPO_PUBLIC_API_URL=http://<your-lan-ip>:3000/api
   ```

   Only the **anon** key belongs here. Never put the service-role key in an Expo
   app. If the Supabase variables are missing the app shows a configuration
   error; it does not fall back to mock data.

2. Install dependencies (PowerShell execution policy blocks bare `npm`, so wrap
   it):

   ```powershell
   cmd /c "npm install"
   ```

3. Start:

   ```powershell
   cmd /c "npx expo start"
   ```

   Then press `a` for Android, `i` for iOS, `w` for web, or scan the QR code
   with Expo Go. For a physical device, `EXPO_PUBLIC_API_URL` must use the
   computer's LAN IP, not `localhost`.

## Structure

```
src/
  app/                 expo-router routes
    (tabs)/            home, explore, saved, alerts, profile
    auth.tsx           login / register / password reset
    search.tsx         search + saved searches
    filters.tsx        filter modal
    opportunity/[id].tsx
    applications.tsx   application tracker
    deadlines.tsx      closing-date reminders
    organization.tsx   company registration and listings
    admin.tsx          role-aware admin dashboard
  components/          existing design system components
  constants/           theme, categories
  lib/                 Supabase client, mappers, error messages
  services/            all database access
  state/               AuthProvider + AppProvider
  types/               shared UI types
  utils/               date/number/text helpers
```

The legacy `src/data/` fixtures are retained for type reference only and are not
imported by runtime code.

## Data flow

- `AuthProvider` owns the Supabase session and profile, listens for auth changes,
  loads the user's admin role, and persists profile edits with a 700 ms debounce.
- `AppProvider` is the only opportunity store. It loads published opportunities,
  refetches on realtime events (debounced), refreshes on app foreground, and
  exposes optimistic bookmark/application/reminder/saved-search actions with
  rollback and error toasts.
- Services map database rows into the existing UI types (`lib/mappers.ts`), so
  the visual layer stayed unchanged.
- Realtime is an enhancement. If the WebSocket is blocked, the app still works
  through pull-to-refresh and foreground refresh.

## Matching

Scores are deterministic and match the database function
`public.match_opportunity_score`:

| Signal | Points |
|---|---|
| Interest / category | 35 |
| Field-of-study keyword | 25 |
| Province or National | 20 |
| Qualification / education | 10 |
| Still open | 10 |

The opportunity detail screen shows the reasons behind the score.

## Auth notes

- Sign-up creates the auth user; a database trigger creates the profile row.
- Email confirmation may be required depending on the Supabase project's Auth
  settings.
- Password reset sends the Supabase reset email. Deep-link handling for the
  mobile reset flow is not implemented yet; use the web/Supabase flow until it
  is.
- Admin access is read from `admin_roles`; UI actions are also hidden for roles
  that cannot use them, but the database enforces every action.

## Validation

```powershell
node node_modules/typescript/bin/tsc --noEmit
```

The project has no unit-test runner configured. Database behaviour is covered by
the SQL suites in `APP/Database/AgriOpportunity_Supabase/supabase/tests/`.

## Known limitations

- No push notifications; notifications and deadline reminders are in-app.
- `npx expo install` fails under the current npm policy (`EALLOWSCRIPTS`); use
  plain `npm install`.
- The reset-password deep link is pending.
- Typed routes are generated by Expo. After adding a route, restart the dev
  server or run the Expo type generation so `.expo/types/router.d.ts` updates.
